# A/B run, 2026-11-27 (from a freeze investigation on the maintainer's PC)

Same PC, same open apps (Opera, VS Code, Claude Code), counters every second (`typeperf`, kept as a CSV),
a Notepad launch every ~1 s for 30 launches right after each flush.

- **A** 21:23:07: the installed 1.2.5 through its task: empty all working sets, write the modified list, purge standby and
  low-priority standby, kill Explorer (`restartexplorer=1`). Logged "freed 1.18 GB (9.5 -> 8.3 GB)".
- **B** 21:25:18: this 1.3 build through the same task, request `ram force` (gentle RAM flush, the 75% threshold off for the
  test only), Explorer restart off (the 1.3 migration). Logged "RAM 10.4 -> 10.4 GB (trimmed 4 idle apps, commands 5)".

**Pass (report's criteria) for B:** every launch under 1.5 s; HDD queue under 2; page-ins at baseline at once; no Winlogon 1002.

Caveats, so the table is not read for more than it shows:

- A was not a full-strength A. An unmeasured 1.2.5 flush ran at 21:20:17 (trigger unknown; it was not one of the test
  scripts) and had already purged the cache, so A threw away little. Even so, A drove page-ins 200 times above baseline and
  queued 5 deep on the HDD. A first flush on a full cache does more.
- The PC did not freeze in either run: this is a load comparison, not a reproduction of the freeze.
- B ran at 32% RAM with the threshold forced off; in normal use 1.3 does nothing at all under 75%.
- `E:` still shows as a disk; its pagefile is no longer configured (only `C:\pagefile.sys` 20 GB).
