# NJ-Flush 1.3: RAM, CPU, GPU and the efficiency guard (design, 2026-11-27)

Owner decisions (2026-11-27): GPU reset by default; the CPU flush calms runaways; the widget keeps RAM first with two thin bars;
tiers stay on RAM. The sent Win+Ctrl+Shift+B was ignored by Windows (measured: DWM VRAM 477 -> 477 MB, no event), so the GPU
reset restarts the display device with `pnputil /restart-device`, with no CUDA skip. Design rules: NJ-Kit `nj-ui-motion-laws`
(L3 one motion, L9 UI under 300 ms, L13/L14 big targets, L15 seven choices or fewer, L17 feedback under 100 ms, L20 no motion on
frequent actions, reduced motion keeps the feedback), Thmanyah Sans, flat cards with 1 px borders, 12 px radius at most,
one accent per resource, no emoji, no gradients in the panel.

## What each flush does

| Flush | Work | Animation | Default hotkey |
|---|---|---|---|
| RAM | leftover helpers, Explorer restart (setting), empty working sets, modified list, standby purge | the toilet, four tiers by RAM | Ctrl+Alt+R |
| CPU | efficiency mode for busy apps: kept at least 90% of one core busy in every 3 s slice of the last 60 s, not the app in front (or its children or same-name processes), same session, not a system process, not a guarded app | exhaust fan pulls the hot steam out | Ctrl+Alt+C |
| GPU | restart the display device (pnputil); VRAM measured before and after | the steamed mirror is squeegeed clean | Ctrl+Alt+G |
| All | GPU (only on a Heavy/Clogged RAM tier or VRAM 85%+, never on an auto-flush, never under a full-screen app; setting), then CPU (setting), then RAM | the bubble bath: soaks while it works, a chip per part ticks, then the plug is pulled | Ctrl+Alt+F (as before) |
| Panel | opens the panel | none (L20) | Ctrl+Alt+P |

Each kind has its own cooldown file (`flush-<kind>.at`); All waits for all three. A request reaches the elevated task through
`request.txt` (`<kind> [auto]`), because `schtasks /run` takes no arguments. Double-clicking `NJ-Flush.exe` is Flush all.

## Widget (158 x 46)

Row 1 RAM % and GB as today; RAM bar coloured by tier; row 2 `CPU` and `VRAM` with thin bars on the same colour scale. Hover:
free RAM, CPU %, VRAM of total and the adapter, the guard count, last flush. Double-click opens the panel (it used to flush). An icon in the hidden icons (like NJ-Sort): left-click opens the panel,
right-click shows the widget's menu, the tooltip carries RAM, CPU and VRAM.
Right-click: Open panel, Flush all, Flush one (RAM, CPU, GPU), Keep apps out of efficiency mode (check), Settings, Preview
animations (all five), then Updates, Uninstall, Close.

## Panel (Task-Manager-like, Jakob's law)

Left: four tiles (RAM, CPU, GPU, Efficiency guard), each name, live value, a 60 s sparkline. Right: the selected page: big value,
a 60 s graph, the facts, the top apps with row actions (End for all; Calm / Restore on CPU), and the page's flush button with its
cooldown counting down. Bottom bar: Flush all (primary, largest target) with its shortcut as a key cap. Lists do not refresh
under the mouse, so a button never moves while you aim at it. Opens instantly, no motion (L20).

## Efficiency guard

Windows 11 and Chromium put background tabs and apps in efficiency mode (EcoQoS + Idle priority), which makes them stutter
when you come back. The guard keeps the apps on its list out of it: every 3 s, from the snapshot the widget already takes
(one kernel call), each listed process in efficiency mode gets EcoQoS off and Normal priority. Default list: the browsers
(msedge, chrome, opera, brave, firefox, vivaldi). The panel page shows what Windows has throttled right now, with Keep out for
each, the guarded list with Remove, the count kept out, and Pause on battery (on). No admin rights, no service, no driver.

## RAM flush after the freeze report (2026-11-27)

Gentle by default: nothing under 75% RAM in use; idle background apps trimmed one at a time; command 5 only; Explorer restart
off (1.2 settings migrated once) and through Restart Manager when on; every flush in `flush.log`. The 1.2 flush is Deep flush.
Measured in `ab-2026-11-27.md`.
